# PRAXIS — лендинг

Реализация утверждённого Landing Concept на базе Brand Core v1.0.

## Стек

- **Astro 5** — статическая сборка, ноль рантайм-JS
- **TypeScript** — строгий режим
- **Нативный CSS** — токены в `src/styles/tokens.css`, scoped-стили в компонентах

Готовая страница: один HTML со встроенным CSS и ~3 KB встроенного JS,
плюс шрифты. Отдельных запросов за стилями и скриптами нет.

## Команды

```bash
npm install
npm run dev           # локальная разработка
npm run build         # сборка в dist/
npm run preview       # просмотр собранного
npm run check         # типы + проверка мёртвых scoped-правил
npm run check:styles  # только проверка мёртвых scoped-правил
```

## Структура

```

scripts/                 служебные проверки

src/styles/motion.css    слой анимации

src/components/hero/     схема первого экрана

src/scripts/             движение и форма заявки
```

## Подключение формы заявки

Форма живёт в модальном окне и открывается всеми кнопками призыва к действию.
Пока `contact.endpoint` в `src/data/config.ts` пуст, форма **не попадает
в сборку вообще**: кнопки работают как якорные ссылки, а разметка и скрипт
формы не включаются. Достаточно вписать адрес обработчика — форма
подключится сама.

Обработчик получает POST с JSON: `{ name, company, contact, process }`.
Подходит Formspree, Netlify Forms или собственный endpoint.

## Правила проекта

Палитра, шрифтовая пара и геометрия знака зафиксированы Brand Core v1.0
(«форма закрыта») и не правятся в рамках проекта. Тексты меняются только
в `src/data/content.ts`.

Придуманных кейсов и клиентов на сайте нет. Цифры в секции «Логика
экономического эффекта» — иллюстрация методики расчёта, что прямо
оговорено на странице.

Кейс «Контент-завод» реальный, но его показатели — предварительные
ориентиры по итогам внедрения, а не замеры. Это отмечено на странице
трижды: меткой ряда «предварительные показатели», знаком «≈» у значений
и оговоркой под блоком. Когда появятся замеры, правится только объект
`cases` в `src/data/content.ts` — разметка секции цифр не знает.

### Три ступени второго плана

`--mute` (#B5B5B5) держит линии, индексы строк и копирайт — то, что
не несёт смысла в отрыве от соседнего элемента. Содержательные
mono-метки идут на `--text-meta` (#6B6B6B, 5.33:1), пояснения и подписи —
на `--text-quiet` (олива, 8.07:1). Роли объявлены в `src/styles/tokens.css`;
шестого цвета в системе не появляется — `--meta` это тон `--ink`.

### Ловушка Astro, о которой стоит помнить

Scoped-класс не пробрасывается внутрь компонента: конструкция

```astro
<SectionHeading class="foo" />
<style>.foo { max-width: 780px; }</style>
```

**молча не работает** — стиль не применяется, ошибки нигде нет. Размеры
и ограничения задавайте пропсами компонента. За этим следит
`npm run check:styles`.

## Что даёт слой движения

Схема первого экрана проигрывается один раз тремя тактами: процесс как
он есть (шаги, возврат на доработку, узкое место) → точка изменения →
процесс после перестройки. Списки, полосы шагов и ряды показателей
проявляются построчно — это включается атрибутом `data-reveal-rows`
рядом с `data-reveal`. Шапка уезжает вперёд и возвращается назад.

Пунктирные линии схемы проявляются масштабом, а не `stroke-dashoffset`:
штрих задан тем же свойством, и анимация подменила бы пунктир сплошной
линией. За это отвечает класс `hd__grow` в `src/styles/motion.css`.

Всё это — прогрессивное улучшение: начальные состояния включает встроенный
скрипт в `<head>`, а если модуль не поднялся за 2.5 с, класс снимается
и страница остаётся полностью видимой. При `prefers-reduced-motion`
не включается ничего.
